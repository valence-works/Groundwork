# Groundwork issue #71 acceptance coverage

This map links the [issue #71 required outcome](https://github.com/valence-works/Groundwork/issues/71) to canonical tests. Keep it aligned with test renames; do not duplicate these scenarios in the provider matrix. All canonical evidence lives on the physical document stores; the portable stores (and their suites) were removed by the ADR 0006 breaking cleanup.

| Requirement | Canonical test evidence |
|---|---|
| Equivalent save returns an authoritative conflict without overwriting | `SqlitePhysicalDocumentStoreTests.UnicodeIgnoreCaseLoadsEquivalentSpellingAndRejectsItsSave`; `RelationalServerPhysicalIdentityConformance.UnicodeIgnoreCaseUsesRetainedOriginalForEquivalentSpelling` (PostgreSQL and SQL Server); `MongoDbPhysicalStorageConformanceTests.Equivalent_identity_save_returns_the_authoritative_original_without_overwriting` |
| Direct load and delete accept an equivalent spelling and retain the original ID | `SqlitePhysicalDocumentStoreTests.UnicodeIgnoreCaseDeleteUsesEquivalentSpellingWithoutBypassingOcc`; `RelationalServerPhysicalIdentityConformance.UnicodeIgnoreCaseDeleteUsesEquivalentSpellingWithoutBypassingOcc` (PostgreSQL and SQL Server); `MongoDbPhysicalStorageConformanceTests.Unicode_equivalent_identity_loads_the_retained_original_spelling` and `.Equivalent_identity_delete_removes_primary_and_linked_records` |
| A terminal unit-of-work failure rolls back prior writes | `PhysicalStorageConformance.UnitOfWorkNonSuccessRollsBackAndMakesTheTransactionTerminal`, instantiated by the SQLite, PostgreSQL, SQL Server, and MongoDB conformance suites; `MongoDbPhysicalStorageConformanceTests.Unit_of_work_identity_conflict_is_terminal_and_rolls_back_prior_writes` |
| Lookup-key collisions expose deterministic provider-neutral diagnostics | `DocumentStoreResultTests.Lookup_collision_exposes_provider_neutral_diagnostic_identity`; provider integrity checks: `SqlitePhysicalDocumentStoreTests.LookupCollisionEvidenceFailsLoadSaveAndDeleteClosed`, `RelationalServerPhysicalIdentityConformance.LookupCollisionFailsLoadSaveAndDeleteClosed`, and `MongoDbPhysicalStorageConformanceTests.Distinct_comparison_keys_with_one_lookup_key_raise_an_identity_collision` |
| Versioned comparison/lookup algorithm drift fails schema evolution closed | `PhysicalSchemaDiffPlannerTests.Identity_algorithm_drift_fails_closed_with_a_dedicated_diagnostic` (`comparisonAlgorithm` and `lookupAlgorithm`) |
| Omitting the case-policy selection remains ordinal | `ExecutableStorageRouteCompilerTests.String_identity_policy_compiles_one_portable_primary_and_linked_identity_route` |
| Non-string identity kinds preserve ordinal projection | `SqlitePhysicalDocumentStoreTests.NonStringIdentityKindsPreserveOrdinalProjection`; `RelationalServerPhysicalIdentityConformance.NonStringIdentityKindsPreserveOrdinalProjection` (PostgreSQL and SQL Server); `MongoDbPhysicalStorageConformanceTests.Non_string_identity_kinds_preserve_ordinal_projection` |
| Cross-provider Unicode, supplementary-scalar, query, mutation, and native-plan parity | Every inherited fact/theory in `DocumentIdentityAcceptanceConformance`, instantiated by `SqliteDocumentIdentityAcceptanceTests`, `PostgreSqlDocumentIdentityAcceptanceTests`, `SqlServerDocumentIdentityAcceptanceTests`, and `MongoDbDocumentIdentityAcceptanceTests` |

Provider-neutral `Contains` rejection remains canonical in `PhysicalQueryPlanCompilerTests.Identity_contains_is_rejected_before_a_physical_plan_is_published`; it is intentionally not repeated by the provider acceptance matrix. Empty identity `StartsWith` is part of the shared matrix because the public comparison contract admits an empty prefix.
